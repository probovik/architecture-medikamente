
# Аудит безопасности данных для "Медикаменте"  

## 1. Процесс записи пациентов

| Категория данны | Методы защиты |
|-------------------|-------------|
| Персональные данные (PII) | Шифрование, RBAC, маскирование, тегирование, аудит доступа |
| Медицинские данные (PHI) Диагнозы, анализы, медкарты| Шифрование, RBAC, тегирование, ключи для доступа к API при обмене, цифровая подпись, аудит доступа| 
| Финансовые данные - договора платежи и т.д. |Токенизация, PCI DSS-шифрование, сегментация, аудит доступа|
| Учетные данные(Логины, пароли сотрудников)| MFA, хеширование|
| Метаданные	Время приема, назначения| Обезличивание|


## Механизм тегирования данных
Помечать чувствительные данные для корректной обработки, контроля и автоматической защиты.

* PII — персональные данные
* MED — медицинская информация
* FIN — финансовая информация
* SENSITIVE — требует аудита и шифрования
* TEMP — временные данные, подлежат удалению

## Инструменты / Меры

* Шифрование файлов	BitLocker, VeraCrypt, EFS
* Шифрование БД	TDE, pgcrypto
* Защита при передаче	TLS 1.3, HTTPS, SFTP
* Контроль доступа (RBAC/ABAC)	Keycloak, Azure AD
* Аудит доступа	SIEM (ELK, Wazuh), Auditd, Microsoft Sentinel
* Тегирование данных	Microsoft Purview, Apache Atlas, Varonis
* Обезличивание / обфускация	Python scripts, Faker, DataMasker
* Защита API OAuth 2.0, JWT, Scopes, Rate limiting
* Контроль экспорта	DLP-системы, в связи с санкциями стоит разссмотреть Ростелеком Solar Dozor DLP
* Разделение доступа по ролям	AD-группы, группы Keycloak, ограничения на файловом уровне
